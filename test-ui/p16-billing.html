P16 · billing: plans, a checkout that survives a crash, webhooks in any order

Dexter does not move money - a provider does, and here it is a mock that behaves like one: it charges once per Idempotency-Key, answers "what happened to this charge?" by Dexter's own reference, and calls back with HMAC-signed webhooks, late and in no particular order. The checkout is Idempotency Mode B: the key is held across the provider call, so a crash between the charge and the record is finished by a retry or the sweeper, never charged twice. A payment is decided once, so a replayed or out-of-order webhook changes nothing. GST is the mock 18 % split - CGST + SGST inside the supplier's state (KA), IGST outside it. Testing aid only - deleted in P19.
